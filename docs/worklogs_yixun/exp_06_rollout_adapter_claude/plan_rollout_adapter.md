## 1. What Yixun asked for

The project goal, restated 2026-08-07: **a good action-conditioned world model for robotics WITHOUT fine-tuning the Wan2.2 backbone.** The Planner's synthesis of exp_01–exp_05 recommended rollout-objective adapter training; Yixun: "go ahead for exp_06".

## 2. Motivation and the hypothesis (recast per F4 — evidence motivates; it does not pre-prove)

Recorded evidence (citations in the exp_02/04/05 worklogs): **E1** — per-clip optimized conditioning drives the frozen 5B to 0.92 SSIM (positive slot, own basin; null slot 0.85): the backbone + a small conditioning channel can render DROID futures; the deployed adapter's 0.2946 sits far below that oracle. **E2** — one-step-trained systems are rollout-compounding-bottlenecked (exp_02's law, r=−0.9994) and per-step-greedy per-clip optimization is basin-locked, while through-the-sampler endpoint optimization lifted capacity and transferred at 72% relative retention (J1b/J1c — 8 clips, null slot, full-horizon). **E3 (THE HYPOTHESIS, not a result):** a state-conditioned ~128M adapter trained through short rollout horizons across thousands of clips × fresh basins amortizes what per-clip full-horizon optimization demonstrated. This is a cross-slot (null→positive), cross-horizon (25→k), cross-regime (per-clip→amortized) extrapolation. **A negative exp_06 outcome does not by itself falsify the rollout-loss family** — it bounds this adapter/horizon/budget cell. The architecture is held fixed FOR ISOLATION of the objective variable, not because E1 proves amortizer adequacy.

## 3. Method

**Model:** the existing `NNXWanSideAdapterStack` pre_context configuration, unchanged (~128M trainable; frozen 5B; bf16 activation-cast contract per the exp_05 §8 audit). The objective is the only manipulated variable.

**Trainer base (F1):** `WanTI2VSideAdapterTrainer` — the production pipeline load (axis_rules), TFRecord loader, sharded state (adapter replicated, data batch-sharded, frozen FSDP), adapter-only optimizer, CFG forward, Orbax restore. exp_06's trainer is a sibling built on those seams. From S7, by GENERALIZATION rounds (not verbatim reuse): the stop-rule pure function (re-targeted per §3d), the accumulation plan + equivalence oracle, the recency-resume/immutable-selection checkpoint discipline, `optional_config_value`. S7's regression train step, cached-target DEV eval, and variance table are NOT used (they have no referent here).

**Primary arm R-B: short-horizon differentiable rollout, k=2 (F8).** k=2 is the predeclared primary (exp_03's validated construction: fixed-k unroll, `lax.scan` + remat, endpoint MSE ÷ (σ_hi−σ_lo)²). k=4 is a separate EXPLORATORY arm, runnable only in an M1-measured cell and never the headline. R-A (corrective scheduled sampling) and R-C (mix) are CONDITIONAL arms admitted only by a recorded Yixun decision after exp_03's S1.5/S1.6 verdicts land, with R-A's p_ss schedule pinned at admission.

**§3a — The CFG gradient contract (F7).** Deployment computes v = v_unc(frozen, T5("")) + w·(v_cond(adapter) − v_unc), w=5. In the unrolled loss: (i) the gradient tree contains ADAPTER PARAMETERS ONLY (the frozen split is structural, S7's closure-seam lesson); (ii) BOTH branches' dependence on the current rollout state z_i is differentiated — no `stop_gradient` on z_i entering either branch (the one-step trainer's stop-grad pattern is NOT copied; it would truncate inter-step gradients); (iii) the architecture's internal stop-grad on block-0 features remains (architecture held fixed). Obligations as code: fixed-input full-rollout output parity with the deployed evaluator path (bitwise at fp32), and a TWO-STEP CENTRAL-FINITE-DIFFERENCE oracle proving inter-step adapter gradients including the unconditional branch's state dependence (the R11 lesson: the FD test is the actual proof of differentiation). **v2.4 (SUPERSEDES the v2.3 clarification, which the T3a reviewer REJECTED and the Planner accepts as its own error): the §3a obligation stands in full and IS discharged autodiff-independently, by ISOLATING the branch term instead of FD-ing the whole loss** — FD `(1−w)·(σ_{s+2}−σ_{s+1})·v_unc(z_1(θ))` against `⟨∇L_full − ∇L_cut-uncond, d⟩` (reviewer-measured on the real fixture: 13.3–107× discrimination at h_rel=3e-3, 109–1004× at 1e-3). The v2.3 reasoning below is retained ONLY as the record of why whole-loss FD fails and why the exact contrast is still required for the conditional branch and for truncations hidden from every AST guard. **Correction: `jax.enable_x64()` DOES exist in JAX 0.10.2** (a scoped, restoring context manager; only the `jax.experimental` spellings are absent) — the earlier 'no float64 fallback' claim was false, though it is now moot. Superseded v2.3 text follows: (1) FD — autodiff-INDEPENDENT — carries the composite claim *inter-step path present vs truncated*, probed along `d = normalize(grad_full - grad_truncated)` (a RANDOM direction is not seed-robust: ratios 0.45-452 over 8 seeds x 3 directions, because the hypothesis gap is a fixed vector a random `d` can be near-orthogonal to; choosing `d` introduces no bias since FD measures the true derivative along whatever `d` it is given, and both hypotheses are evaluated along the same `d`). (2) EXACT GRADIENT CONTRAST — no numerical floor — carries the finer per-branch attribution (module vs stop-grad-on-unconditional vs stop-grad-on-conditional, relative-L2 margins asserted per seed). Evidence FD cannot do (2): the exact per-branch effect grows with guide scale (relL2 0.010/0.031/0.105 at w=5/15/40) while the FD ratio stays <= 0.99 — noise grows with signal; and `jax.experimental.enable_x64`/`disable_x64` DO NOT EXIST in JAX 0.10.2, so the float64 fallback is unavailable and a global flag flip is forbidden. The contrast is load-bearing, not decorative: it is the ONLY thing that kills truncations hidden from every AST guard (`jax.lax.__dict__["stop_"+"gradient"]`). **The site NOT to copy is confirmed (T1-6): `trainers/wan_ti2v_side_adapter_trainer.py:180-187` stop_gradients BOTH `z_t` entering the unconditional branch AND `v_uncond` itself — correct for a one-step objective, gradient-truncating for a rollout one.**

**§3b — Noise/support policy (F8), pinned:** one support draw PER BATCH (exp_03's convention); start position σ_hi uniform over the legal starts, i.e. **every start whose k-step window ends at or before the last non-terminal grid index — terminal σ=0 is never a start AND never an endpoint** (v2.2 clarification, T1 finding 1: v2.1's "{1..N−k}" was a 1-BASED expression of exactly the set exp_03's pinned 0-based construction draws, `start ∈ {0..N−k−1}`; the pinned construction is authoritative and was implemented verbatim — the two readings denote the same set, and the 0-based literal reading of the old wording would have contradicted this clause's own terminal-σ exclusion); fresh ε per draw (**no ε purpose exists at the pin — exp_03 drew ε from its shared training stream; T3b adds one additively, name-hashed so every existing draw stays bit-identical**, T1 finding 4); PRNG derivation resume-stable and accumulation-stable: fold_in(seed, global_step) then per-purpose fold (the exp_03 `exp03_aux_key` pattern, merged at T1); C0 and R-B consume THE SAME batch stream (identical data order at matched seeds) so the comparison is paired at the data level.

**§3c — Primary gate (F6), as code:** a NEW `pos_rollout_gates.py`: mean PAIRED per-example ΔSSIM(R-B − C0) on DEV-64 ≥ **+0.05** AND paired-bootstrap (10k, seed 20260804) CI-low **> 0**; coverage/imputation rules inherited (claim-penalizing); manifest-hash-bound. TEST-64 confirmation (same paired form) only after the DEV gate passes. **Anchor protocol:** before any new-arm scoring, (1) reproduce the historical checkpoint's recorded 4-sample validation (0.2946) within a predeclared tolerance — the wiring proof; (2) freeze the historical checkpoint's DEV-64 table under the new protocol — the benchmark row every table carries.

**§3d — Selection/stop metric (F9, cadence pinned per pass-2):** a deterministic FIXED-DRAW DEV-64 rollout-loss estimand — per (example, eval) a pinned (support, ε) pair (the exp_02 D2 instrument pattern), manifest-bound to DEV-64, TEST-64 structurally excluded (the config's eval source points at the DEV manifest, not the val directory; a test pins that no TEST name is ever read during training). **Evaluation and checkpoint-selection cadence: every 1,000 updates, identically for R-B and matched-C0** (a YAML-declared key, config-drift-pinned). S7's stop rule generalized to this metric; the identical rule runs on matched-C0. Checkpoint metadata carries the metric + arm + k.

**§3e — THE ACTION-USE GATE (F3, mandatory; shuffle contract per pass-2).** The project goal is ACTION-conditioned prediction; SSIM alone cannot certify it. For the selected checkpoint AND matched-C0: paired evaluations on identical examples and identical noise under {true actions, wrong actions, zero actions}; diagnostic row: adapter-disabled frozen backbone. **The wrong-action assignment is a COHORT-LEVEL seeded derangement** (the deployed evaluator runs batch-1, so within-batch shuffling is undefined): one derangement of the 64 example names per cohort, derived independently for DEV-64 and TEST-64 from a pinned seed, validated to have NO fixed points and NO byte-identical replacement action sequences (**v2.6, T5b: repair by BIJECTIVE SWAP, failing closed when no legal swap exists — NOT the non-bijective overwrite v2.5's 'advances to the next legal target' also permitted. A non-bijective assignment changes the marginal distribution of action sequences, so the wrong-action condition would differ from true in more than its pairing and the gate would no longer isolate action USE. With 64 distinct trajectories the fail-closed path is a tripwire, not a routine.**), with the permutation and its hash PERSISTED in the eval artifact; each example is then evaluated batch-1 with its mapped example's actions. **Gate: mean paired ΔSSIM(true − wrong) CI-low > 0 on DEV-64**, repeated on TEST-64 at confirmation. Reported (not gated): Δ(true − zero), and the C0 row (does one-step training use actions more or less than rollout training — a finding either way).
