# Plan review: exp_02 overfit100
Reviewer: OpenAI Codex gpt-5.6-sol (xhigh), 2026-07-28

## Context loaded
- Experiment SOP — review gates, TDD cycles, validation ladder, launch approval, and reproducibility requirements.
- exp_02 queries — 100 random successful trajectories, random non-empty instruction, view 0, full DiT fine-tune, and LR 1e-5.
- exp_02 worklog — aligned GCS annotations contain text/success while episode `.pt` latents remain structurally unverified.
- exp_01 analysis/results/plan — full-corpus training reached train SSIM 0.787 without establishing per-clip memorization or a reconstruction ceiling.
- exp_02 candidate plan — direct latent-window build, episode-indexed T5 table, 10k-step full fine-tune, and 16-window evaluation.
- Merged code — full-FT trainer/objective, Wan prompt encoding and padding, rollout/evaluation paths, base configuration, and raw-DROID reader.

## Verdict
REQUEST-REVISION. The 100-trajectory, text-conditioned direction is appropriate, but the plan incorrectly treats language plus one frame as a determined future and currently cannot execute its claimed text-conditioned evaluation with the merged exp_01 tooling. The latent-conditioning semantics, evaluation coverage/ground truth, text-table memory path, and staged compute budget must be resolved before implementation or TPU approval.

## Findings

1. **F1 — BLOCKER — The determinacy claim is scientifically overstated.** The plan claims text plus the first frame “makes the task determined” and treats exp_01’s 0.787 SSIM as a plausible ceiling. A DROID instruction identifies a goal, not the recorded motion timing, gripper path, object trajectory, pauses, or camera dynamics; multiple futures remain compatible with the same semantic condition. Conversely, on a finite training set, even exp_01 could theoretically memorize targets from unique first-frame fingerprints, so its result is not an established conditioning ceiling. Rewrite the hypothesis as a **finite-set memorization test**: success may show that the weights memorize a mapping from nearly unique inputs, not that text makes the physical future determined. Audit duplicate/near-duplicate `(instruction, z_i0)` conditions, add correct/null/shuffled-text rollout controls, and do not infer a pipeline defect from failure. If true input-level determinacy is required, add aligned action sequences or an explicit episode/window identifier.

2. **F2 — BLOCKER — The proposed evaluation path does not support `OVERFIT100_TI2V`.** D8 says exp_01’s reviewed tools will be retargeted, but `generate_wan_side_adapter.py` requires an `actions` feature, recognizes only `model_type == "FULL_FT_TI2V"`, broadcasts null context, and otherwise enters the adapter branch. `eval_wan_full_ft_val_loss.py` likewise rejects any other model type and evaluates null context. Neither tool produces the claimed residual video. The planned trainer also adds `episode_index`, while inherited `_data_shardings()` has only `z_i0`, `z_video`, and `actions`, causing a JIT tree mismatch. Add explicit planned generator and full-loss-evaluator changes—or new overfit100-specific modules—with the new schema, full-FT restore path, per-example context gather, episode-index sharding, residual output, and checkpoint round-trip/inference tests.

3. **F3 — BLOCKER — The acceptance measurement cannot support “reconstruct the training samples.”** Sixteen windows cover only 16 of 100 episodes and roughly 16 of 1–2.5k training windows; a high cohort mean can hide widespread failures. Evaluate at least one canonical window from every episode at intermediate checkpoints and all built windows at the final candidate checkpoint; use multiple fixed noise seeds on the 100-episode cohort. Predeclare mean, median, lower percentile, minimum or fraction-above-threshold—not an unspecified “cohort SSIM”—and replace `latent MSE ≤ ~0.05` with an exact rule. Primary pixel SSIM should compare the prediction with the VAE decode of cached target latents. Raw MP4 frames are a useful auxiliary only after exact frame/crop alignment and measurement of the target-VAE-to-RGB ceiling; their availability does not remove the VAE-decode caveat.

4. **F4 — BLOCKER — `z_i0 = z_video[:, s]` is not yet proven to be first-frame-only conditioning.** Exp_01 stored separate `z_I0.pt` and `z_video.pt`, whereas D4 proposes slicing the full-trajectory latent. Unless temporal causality and encoding parity are verified, that slice may differ from the TI2V image-conditioning encoding or contain temporal context from neighboring/future frames, invalidating the experiment. Inspect a real `.pt` before locking the build contract, establish its container key, axes, dtype, normalization, temporal scale, and raw-frame mapping, and numerically compare a matched aligned window against exp_01’s cache or re-encode the exact first RGB frame through the TI2V conditioning path. If they differ, build `z_i0` with the actual image-conditioning encoder rather than slicing `z_video`.

5. **F5 — MAJOR — Prompt encoding is API-compatible but the memory and padding contracts are incomplete.** `encode_prompt` accepts a list of distinct prompts, tokenizes to length 512, passes an attention mask through UMT5, truncates to each true length, and then zero-pads the embeddings. The Wan TI2V forward explicitly sets `encoder_attention_mask=None`; its text cross-attention also discards that mask, so `mask_padding_tokens: true` does not create a per-prompt semantic padding mask. Exp_02 should preserve this same zero-padded pipeline behavior, not invent a new mask. Encoding all 100 together is unsafe without a host-memory measurement and also needlessly encodes 100 negative prompts through the public helper. Use a configurable bounded loop/minibatch, test loop-versus-batch/order parity, and validate the table against the committed manifest. The bf16 table is exactly 400 MiB replicated per chip, so D7’s “HBM story is unchanged” is false; include its sharding and physical bytes in the startup audit and make the fit probe authoritative.

6. **F6 — MAJOR — The frozen-list reproducibility claim is too strong.** Selection depends on success annotations, object existence, and latent length in a dataset explicitly observed while uploads were ongoing; therefore the seed alone cannot reproduce the selection. Make a committed build manifest—not rerunning selection—the authoritative rebuild input, recording selected/rejected IDs, chosen/raw instructions, source object generations or hashes, sizes, latent metadata, and builder commit. Fail if any source fingerprint changes. The new aligned builder is preferable to `droid_video_dataset.py`: that reader uses raw TFDS, chooses between two cameras, detects success from the file path, and can select an empty instruction. Reuse its stateless-selection idea/tests only, not its data path.

7. **F7 — MAJOR — The first compute decision is unnecessarily expensive and late-observing.** At approximately 2k windows, GBS 256 gives about eight updates per nominal pass; 10k steps is roughly 1,250 passes, while fresh noise/timesteps make each presentation stochastic. LR 1e-5 is user-locked and defensible, but a 500-step warmup already spans about 60 passes and the first rollout checkpoint at 2,500 arrives after roughly 300 passes. Make 2,500 steps a resumable first segment with earlier observations around 250/500/1,000/2,500, then continue to 10k only if necessary. Probe v6e-8 with a smaller GBS such as 32 before assuming v6e-64/GBS 256 is optimal, and place a one/few-clip or 10-episode overfit sanity gate before—not after—a failed 10k run.

## The determinacy question

SSIM ≥ 0.95 is reachable **in principle** on this finite training set if every `(instruction, first-frame latent)` effectively identifies one target and the 5B weights memorize that lookup; the learned flow can then map fresh noise to the recorded target. It is not guaranteed, and language plus one frame does **not** determine the recorded future in the causal or generalization sense.

I would tell the user: run exp_02 as a memorization-capacity test, but do not describe text as removing all ambiguity or interpret failure as proof that the pipeline is broken. Success would show that the weights can recite these samples, potentially using unique visual fingerprints more than language. For a genuinely determined reconstruction test, condition on the aligned action sequence or an explicit episode/window ID; for the cleanest pipeline sanity bound, first prove near-perfect reconstruction on one or a few fixed clips.
